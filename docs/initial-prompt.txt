HISTORICAL INITIAL REQUEST — not current workflow instructions.

In this directory is a git repo for a project on converting LaTeX files (.tex) to literate agda files (.lagda.md). These are being prepared for a math research project, led by a small team (none of whom come from a programming background) who are primarily interested in mathematics. Previously, these were being done by a different collaborator using an AI agent, but we are interested in having a script or program that can perform these conversions.

This repository contains a "skills" directory which was being used by the AI agent at an earlier point in time. Importantly, you are NOT to interpret these skills literally. Instead, your job is to understand the underlying instructions contained in these files and make sure the script correctly implements these instructions as part of the conversion. The script should run without user intervention, and this takes priority over any instructions contained in the older skills files about asking for permission before making edits/changes. (That said, you should of course NEVER try to sneak around or circumvent permission issues while you are working.)

The first step is to create a plan for writing this script. Some important points to consider:
 1. It makes sense to use Python, since it's a safe bet that all collaborators have python installed on their machines. Is there possibly a better option though?
 2. Given that the project consists of individuals who are less familiar with programming, it is very important that the code is clear, easy to both understand and independently verify.
 3. There already exists software for converting latex to ordinary markdown files: called Pandoc. However, we need literate agda files, which are markdown files with additional functionality for agda code blocks. Is it easier to use Pandoc and add custom functionality for our use case, or to create our own script from scratch?
 5. Every theorem, definition, remark, or other itemized environment in the LaTeX code needs to have its number included in the output .lagda.md files, matching the numbers when compiled in LaTeX.
 4. Agda codeblocks need to be added for every definition, every mathematical result (e.g. propositions, lemma, theorem), and every proof. More detailed instructions may be included in the files inside this repo. You'll need to add these code blocks independently of the script, using code copied verbatim from the agda-unimath library. You may add these code blocks before or after the script processes the files, but they must be added at some point.
 5. There should be files already converted in this repo; these provide a template for the correct output, style, content, and the like. A great criterion for success here is if we can reproduce these examples using the script and your inserted codeblocks.

In connection with point 4, these agda codeblocks need to be independently verified by a human collaborator. It would be best if there were, in addition, a simple program or.html file (prefereably with a UI but not necessary) that shows definition/proposition/theorem and proof, its corresponding agda codeblock, and the source of this agda codeblock within the agda-unimath library, showing the code in agda-unimath (maybe from the website, but could also be from a github file) side-by-side. I'm thinking it would be best if a user is prompted to go through each block, with the user given the following controls: (a) mark the current codeblock as accepted/verified, (b) add a comment for other reviewers to see, (c) go to the next code block/prompt, and (d) go to the next code block/prompt. Actions such as marking the codeblock as accepted or adding a comment should be stored in some file in the repository so that it can be shared with the other collaborators. The other collaborators in this repository should also be able to run this program, easily see when a codeblock is marked as accepted, see any comments alongside this, and go through all the same prompts as well.
